# Embedded sample clip

`main.mp4` is baked into every build with `//go:embed` and is used when a
`kind=file` profile has an empty `media_file_path`. It lets `serve` (and the
`farm` test rig) produce a working RTSP stream with no external media and no
ffmpeg pre-generation step.

It is a synthetic test pattern generated by this project with ffmpeg/x264 —
no third-party footage. The current file was produced with a command equivalent
to:

```bash
ffmpeg -y -f lavfi -i "testsrc2=size=1280x720:rate=30" \
  -t 6 -c:v libx264 -profile:v high -pix_fmt yuv420p -crf 23 \
  -movflags +faststart main.mp4
```

(x264 defaults apply: `keyint=250`, `bframes=3`. The clip is shorter than one
keyframe interval, so playback starts on the IDR at the head of the file.)

Notes:

- H.264 only. aiovms (and browsers) reject H.265, so do not replace this with
  an HEVC clip.
- Keep the file small (a few hundred KB): it is compiled into every binary.
- Keep a keyframe at the start (`-g` small enough, or start on an IDR) so the
  looper's first frame is independently decodable.
- 1280x720@30 is what `GetVideoEncoderConfiguration` reports for the embedded
  fallback, so a replacement with a different geometry changes that metadata.

To regenerate after changing the command:

```bash
cd internal/rtsp/assets && ffmpeg ... && go test ./internal/rtsp -run TestEmbeddedSampleSourceSmoke -v
```
